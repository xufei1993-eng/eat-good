# 内容管理后台

这是第一阶段的轻量管理后台，直接调用微信云开发的 `catalog` 云函数。

## 使用

1. 在云开发控制台创建 `foods` 和 `dishes` 两个集合；客户端权限设为禁止直接读写，所有访问统一经过云函数。
2. 给 `catalog` 云函数设置环境变量 `CATALOG_ADMIN_TOKEN`，使用一段独立的高强度随机密钥。
3. 在微信开发者工具中上传并部署 `cloudfunctions/catalog`，首次部署选择“云端安装依赖”。
4. 在 CloudBase「身份认证 → 登录方式」开启匿名登录（v2）。
5. 在「环境设置 → 安全来源」添加 `localhost:8080`；若用 `127.0.0.1` 打开，还要单独添加 `127.0.0.1:8080`，配置通常需要几分钟生效。
6. 用静态服务器打开 `admin/index.html`。直接双击打开时，部分浏览器会拦截 SDK 请求，推荐在项目目录执行 `python3 -m http.server 8080` 后访问 `http://localhost:8080/admin/`。
7. 首次保存或上下架时输入 `CATALOG_ADMIN_TOKEN`。密钥只保存在当前浏览器标签会话中。

## 批量导入 3000 道菜

1. 先重新部署 `cloudfunctions/catalog` 云函数，使分页查询、菜系筛选和 `searchText` 字段生效。
2. 打开 `admin/index.html`，完成匿名登录后切换到「菜品库」。
3. 点击「导入 3000 道菜」，输入云函数环境变量中的 `CATALOG_ADMIN_TOKEN`。
4. 导入按每批 20 条执行，使用稳定 `sourceKey` 幂等覆盖；重复点击不会重复创建。

内置文件为 `admin/builtin-dishes.json`，共 3000 条。扩展条目标记为 `source: generated-curated`、`nutritionBasis: template-estimate-v1`，营养值是标准份食材估算，后台可继续编辑或下架。
8. 在“菜品库/食物库”中新增、编辑、上架和下架数据。记录页会优先读取线上状态为 `online` 的数据。
9. 部署最新版 `catalog` 云函数后，可在“菜品库”点击“导入内置菜品”，把代码中的内置目录分批新增或更新到云端。该操作可重复执行，不会重复创建同一条内置数据。
10. 菜品和食物可填写图片 URL，或选择 JPG/PNG/WebP 图片上传到云存储（单张不超过 2MB）。再次导入内置菜品时，已人工配置的图片会保留。

## 份量与计量单位

- `measureUnit` 取 `g` 或 `ml`，分别表示重量与容量。
- `servingAmount` 是一标准份的数值，例如咖啡为 `300`，计量单位为 `ml`。
- `nutrition` 保存这一标准份的营养总量；小程序会先折算成每 100g 或每 100ml，再按用户实际输入量计算。
- 旧数据仍可保留 `servingGrams`。新版云函数会兼容读取，但液体新数据应使用 `servingAmount + measureUnit`。
- 饮用水等零热量饮品允许保存 `0 kcal`；未填写热量和明确填写 `0` 会被区别处理。

本次单位字段上线时，需要重新部署 `cloudfunctions/catalog`，再在菜品库点击一次“导入内置菜品”，才能把液体的 `ml` 元数据同步到云端。

历史本地数据不会自动覆盖云端；云端为空时，小程序继续使用现有 JS 目录作为离线兜底，便于逐步迁移。
